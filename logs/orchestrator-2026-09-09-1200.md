## Goal

Route별 TTFT 측정의 probe timeout·동시성·freshness 동작을 강화한다.

## Actions

- provider slot 대기 2초와 실제 upstream probe timeout 10초를 분리했다.
- probe cycle에 최대 4개의 bounded worker를 적용하고 cycle 종료 시 worker를 join한다.
- latency registry에 probe/request 최신 시간을 기록하고 fresh probe → fresh request 순서로 route TTFT를 선택한다.
- 90초를 넘긴 TTFT는 routing ranking에서 제외했다.
- control 응답에 `performanceKnown`을 추가해 latency-only 값을 benchmark performance로 표시하지 않게 했다.
- Model 탭 polling이 table body만 갱신하게 했다.

## Files Changed

- `internal/probe/probe.go`: slot/upstream timeout 분리 및 bounded concurrent probes.
- `internal/latency/latency.go`: fresh TTFT lookup.
- `internal/latency/latency_test.go`: stale probe의 request fallback 회귀 테스트.
- `internal/gateway/performance.go`: fresh TTFT routing 적용.
- `internal/gateway/control.go`, `internal/control/api.go`, `internal/control/server.go`: performanceKnown 노출.
- `desktop/frontend/app.js`: Model tab polling 및 performance 표시 보호.

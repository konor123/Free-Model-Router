## Goal

Diagnose and fix the reported blank Model Manager and unresponsive tray behavior before the v0.8.0 feature work.

## Actions

- Reproduced desktop behavior on Windows and identified synchronous auxiliary WebView construction as a documented Tauri Windows deadlock risk.
- Moved auxiliary window creation off synchronous command and tray event paths, with duplicate-creation guards.
- Reproduced the remaining empty model list and found that the raw Rust HTTP bridge passed chunked transfer framing to JSON parsing.
- Added strict HTTP chunked-body decoding and framing regression tests.
- Manually verified a release build opens Model Manager, renders 70 models, remains responsive, and opens Usage Log from the tray.

## Files Changed

- `desktop/src-tauri/src/main.rs`: Added safe auxiliary-window scheduling, raw HTTP chunk decoding, and related regression tests.
- `desktop/frontend/app.js`: Prior desktop model/log UI changes remain pending consolidation into the planned tabbed interface.

## Result

- Success: Model Manager is populated in manual Windows verification after decoding chunked control responses.
- Success: Tray context menu displayed and opened Usage Log without freezing the desktop process.
- Rust tests reached 14 passing tests during the diagnostic cycle.
